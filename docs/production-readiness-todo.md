## 一、依赖完整性与版本兼容性

### TODO-P1: 锁定依赖版本
**问题**: package.json 使用 `^` 范围，可能导致版本不一致
**实施方案**:
1. 将关键依赖版本锁定为精确版本
2. 特别是 ai、@ai-sdk/*、xstate、electron
3. 生成 package-lock.json 并提交
**验证**: `npm ci` 验证锁定版本

### TODO-P2: Electron 原生模块重编译
**问题**: better-sqlite3 需要与 Electron Node ABI 匹配
**实施方案**:
1. 添加 `electron-rebuild` 到 devDependencies
2. 在 build 脚本中添加重编译步骤
3. 测试打包后的应用
**验证**: `npm run build:win` 验证打包

### TODO-P3: 移除开发依赖
**问题**: 部分 devDependencies 不需要打包到生产
**实施方案**:
1. 检查 electron-builder 配置
2. 确保 devDependencies 不被打包
3. 优化打包体积
**验证**: 检查打包后的应用大小

## 二、功能完整性

### TODO-P4: 流式预览功能修复
**问题**: XState actor 覆盖名不匹配，流式预览失效
**实施方案**:
1. 修复 `electron/ipc/workflow.ts` 中的 actor 覆盖
2. 将 `generateReport` 改为 `generateModules`
3. 测试流式预览功能
**验证**: 生成报告时观察实时预览

### TODO-P5: builtin 知识加载竞争条件
**问题**: main.ts 和 knowledge.ts 可能重复加载
**实施方案**:
1. 添加加载锁机制
2. 使用数据库唯一约束防止重复
3. 测试并发加载场景
**验证**: 多次启动应用检查重复加载

### TODO-P6: 错误恢复机制完善
**问题**: 部分错误场景缺少恢复机制
**实施方案**:
1. 为所有 IPC 处理器添加重试逻辑
2. 为数据库操作添加事务支持
3. 为 LLM 调用添加降级策略
**验证**: 模拟错误场景测试恢复

## 三、安全性

### TODO-P7: API Key 加密存储
**问题**: API Key 明文存储在 SQLite
**实施方案**:
1. 使用 keytar 库加密 API Key
2. 修改设置保存和读取逻辑
3. 添加迁移脚本处理旧数据
**验证**: 检查数据库中 API Key 是否加密

### TODO-P8: 生产环境禁用 DevTools
**问题**: 用户可以通过快捷键打开 DevTools
**实施方案**:
1. 在生产环境禁用 DevTools 快捷键
2. 移除菜单栏中的 DevTools 选项
3. 添加配置选项（调试时可开启）
**验证**: 打包后尝试打开 DevTools

### TODO-P9: 输入验证完善
**问题**: 部分 IPC 处理器缺少输入验证
**实施方案**:
1. 为所有 IPC 处理器添加参数验证
2. 添加长度限制和类型检查
3. 返回友好的错误消息
**验证**: 发送无效参数测试
